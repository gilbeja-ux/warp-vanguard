# Warp Vanguard — best-practice audit (2026-09-06)

A review of the game at version 1.0.7 against current practice for mobile games,
Google Play, the App Store, and the Capacitor stack. Every claim below was read
in the code or measured. Items already closed in `docs/HOUSEKEEPING.md` are not
repeated. The previous audit is `docs/AUDIT-2026-08-21.md`.

**Verdict:** the engineering is in good shape. `npm test` passes, the deployed
verifier is in sync (`a21d4685c45d` both sides), the store icon is opaque, R8
is on with keep rules, versions are generated, both shells are pinned. The gaps
are two real defects in the native shell and the error path, then a short list
of store and accessibility practice the game does not do yet.

Severity: HIGH = fix before production. MED = fix soon. LOW = when convenient.

---

## 1. Defects

**All four FIXED 2026-09-06** (same day, one batch, both shells): `npm test` gained
three sections (THE ERROR NET, THE BACK BUTTON, THE ANDROID SHELL), the Android
debug APK and the iOS simulator app both compile with `@capacitor/app`, and the
behavioural fingerprint shows 0 of 41 boards moved. The byte-level sim id moved,
so the next store cut deploys the verifier `--compatible` as usual. Owed on a
device: the back button on Android 16 with predictive back, and a light-mode
launch showing navy behind the icon zoom.


### D-1 (HIGH, FIXED) — The Android back button exits the app at once, mid-run included
- `@capacitor/app` is not installed (`node_modules/@capacitor/` holds android,
  cli, core, haptics, ios). No file in `src/game/` listens for `backButton`.
- Capacitor 8 core has no back handling of its own: `grep -ri backpress` over
  `node_modules/@capacitor/android/capacitor/src/main/java/` finds nothing. The
  OS default applies: the activity finishes.
- A player who presses back during a lane loses the run with no pause and no
  confirmation. On Android 16 with target 36, predictive back is on by default,
  so the system also plays the "leave app" animation.
- **Fix:** add `@capacitor/app`, listen for `backButton`. In `S.PLAY` → pause.
  On a disc → close it, the way `Escape` does at `60-input.js:318-321`. On the
  home menu → `App.exitApp()`. Verify on an Android 16 device with predictive
  back. iOS has no back button; the same handler serves the gamepad B button.

### D-2 (HIGH, FIXED) — A JavaScript error freezes the game, and nobody hears about it
- `frame()` in `99-boot.js:875-1112` has no try/catch. The next
  `requestAnimationFrame(frame)` is the last statement, so a thrown error ends
  the loop. The canvas holds its last frame forever.
- No `window.onerror` and no `unhandledrejection` handler exist in `src/game/`.
- Play Console vitals see native crashes and ANRs only. A WebView JS error is
  invisible to Play, to App Store Connect, and to you.
- **Fix, two parts:** (1) wrap the frame body; on an error, log it to a
  `lastError` slot in the save blob, re-arm the loop, and show a disc:
  "THE LANE BROKE — TAP TO RESTART". (2) Offer the stored error through the
  existing FEEDBACK disc as a one-tap "SEND THE ERROR". The player chooses, so
  the Data Safety form does not change. No analytics SDK, no new processor.

### D-3 (LOW, FIXED) — The Android launch theme leaves its colour to the system; the placeholder splash files are dead weight
- **Corrected 2026-09-06 after Gil's observation.** The first draft called this
  HIGH and claimed a white flash with the Capacitor logo. That was inferred from
  the resource files, not observed. Gil sees the launcher icon zoom and centre
  on a black ground, then the game's own splash. That is the Android 12+ system
  splash, which covers the window until the WebView has painted navy, so the
  placeholder image never gets a visible frame.
- What remains true: every `android/app/src/main/res/drawable*/splash.png` is
  the stock Capacitor image (dated 2025-03-31) and ships in the APK unseen.
  `styles.xml` sets no `windowSplashScreenBackground`, so the ground behind the
  icon zoom is the day/night theme's default. In dark mode that is near black
  and matches the game. In light mode it may be white.
- **Tested by Gil 2026-09-06:** light mode shows a white ground. Fixed: the
  theme now sets `windowSplashScreenBackground`, `windowBackground` and
  `background` to `#03060E`, the eleven placeholder files are deleted, the
  theme is tracked, and `capacitor.config.json` carries the Android twin of the
  iOS web-view colour.
- **Hygiene:** delete the ten placeholder files, point the theme at a navy
  colour drawable, add `"android": { "backgroundColor": "#03060e" }` to
  `capacitor.config.json` to mirror the iOS key, and pin the colour in
  `npm test` beside the iOS launch-screen pin.

### D-4 (LOW, FIXED) — No 1.0.7 entry in `docs/CHANGELOG.md`
- The latest heading is 1.0.6. Commit 7b9a98e cut 1.0.7 for open testing.

## 2. Store practice

### S-1 (MED) — Confirm the Play testing gate before you plan a launch date
- A personal developer account created after 2023-11-13 must run a closed test
  with at least 12 opted-in testers for 14 continuous days before it can apply
  for production access. `RELEASE-PLAN.md:238` says "verify the current
  threshold". Check the account type in Play Console → Developer account. If it
  is personal, the 14-day clock is the launch date, so start it now.

### S-2 (MED) — Read the pre-launch report on every track upload
- Play runs the AAB on real devices and records crashes, ANRs and screenshots.
  It would have caught the R8 bridge death at launch. Nothing in the repo or
  the docs names it. Add it to the AAB routine in `RELEASE-PLAN.md`.

### S-3 (MED) — An in-app review prompt, on both platforms
- No review request exists. `@capacitor-community/in-app-review` wraps Play
  In-App Review and `SKStoreReviewController` in one call.
- Ask once, at the contract 1 boss verdict. It is the peak-satisfaction seam the
  1.1 paywall already targets. Never gate anything on it; the OS caps repeats.

### S-4 (MED) — Tablet screenshots
- `docs/store/` holds seven phone shots at 1920×1080 and no 7" or 10" set.
  The listing says "phone only". The orientation-lock large-screen warning is
  accepted, but a tablet set still raises the listing's quality score and
  Play accepts 16:9 there too. The harness that made the phone shots can
  re-export at 2560×1600 in minutes.

### S-5 (MED) — Write the App Store Connect twin of `PLAY-CONSOLE-ANSWERS.md`
- The two-platform law says iOS is one archive from upload. The binary is; the
  paperwork is not. App Privacy labels (Identifiers → User ID; Usage Data →
  Other; User Content → Other), the age rating, and the review notes for the
  anonymous identity and the tester passcode are all derivable today.
- `ITSAppUsesNonExemptEncryption` is already in the plist. The app target
  uses no required-reason API, and Capacitor's pods ship their own
  `PrivacyInfo.xcprivacy`, so no manifest is owed.

### S-6 (LOW) — Store listing translations
- Zero code cost: the listing copy can carry a Hebrew translation now. The game
  text itself is canvas-drawn in a Latin-only face; treat that as a later job.

## 3. Player practice

### P-1 (MED) — A leaderboard opt-out toggle
- `PLAY-CONSOLE-ANSWERS.md` already names it: a settings row read before
  `lbSubmit`. It turns two required Data Safety rows into "users can choose",
  strengthens the legitimate-interest position, and costs one row in the
  settings disc.

### P-2 (MED) — Comfort and accessibility knobs
- The settings disc has three rows: SFX, MUSIC, HAPTICS (`91-briefing.js:1998`).
  There is no way to reduce `shake` and `redFlash` (`72-tick.js:174-175,
  437, 632`) and `prefers-reduced-motion` is not read.
- Add one row, MOTION: FULL / REDUCED. Reduced sets shake and flash gains to
  zero and shortens the warp spool. Photosensitivity is a store-review topic on
  both platforms and a real player need.
- Colour carries the rule (red, blue, white, purple). The 1.0.5 hulls name the
  role by silhouette and the emitters differ by pitch, so the base is good.
  Prove it once: render a stage-05 frame headless, pass it through a
  deuteranopia matrix, and check blue vs white vs purple stay apart. Add a
  HIGH CONTRAST palette only if that check fails.

### P-3 (LOW) — Funnel numbers without analytics
- There is no analytics SDK, by design. The 1.1 paywall price still needs a
  reach number. `runs` already tells you which stage boards get rows per player
  id. One SQL view over data you already hold answers "how many reach stage
  08" with no new collection and no policy change.

## 4. Stack and hygiene

### T-1 (MED) — Supabase advisors
- 17 functions carry a mutable `search_path` (WARN). One migration fixes all:
  `alter function public.<name> set search_path = public, pg_temp;` for each.
- `runs_backup_20260902` (172 rows) sits in `public` with RLS on and no policy.
  Deny-all is safe, but drop it or move it to a private schema once 1.0.7 has
  proven the wipe.
- `rls_auto_enable` is flagged as anon-executable. It is an event-trigger
  function (returns `event_trigger`) and cannot be called through RPC. False
  positive; note it and move on.
- Leaked-password protection is irrelevant: auth is anonymous only.

### T-2 (LOW) — Minify the shipped JavaScript in `dist/` only
- `dist/game/` is 1.9 MB of unminified source; a phone parses it on every cold
  start. Terser in `scripts/build.js` would roughly halve it. The sim id hashes
  `src/`, not `dist/`, so no board id moves. Measure cold start on the phone
  with `scripts/bench.js` before and after; that is the house rule.

### T-3 (LOW) — CI builds neither shell
- `.github/workflows/test.yml` runs the suite and the verifier bundle. A
  `./gradlew bundleRelease` job (debug-signed, no key) would catch Gradle and
  AGP rot between store cuts for free. The iOS twin needs a macOS runner and is
  optional.

### T-4 (LOW) — Verified as good, no action
- `npm test` passes, three suites. Verifier in sync.
- `docs/store/wv-512-store.png` is 512×512 and fully opaque (alpha histogram
  is 262144 × 255). The 2026-08-21 R-7 item is closed.
- No optional chaining or nullish coalescing in `src/game/`, so old WebViews
  on API 24 devices parse the bundle.
- Service worker is skipped under Capacitor; fonts are preloaded; DPR is
  capped at 2; render is capped at 60 Hz; dt is clamped; the sim is fixed-step.
- Release keys are ignored by git before any exists. R8 keep rules are tracked.
- Rate limits, RLS deny-by-default, JWT identity, private traces bucket,
  frame-hash binding: all in place.
