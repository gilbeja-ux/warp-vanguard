# Warp Vanguard — skills audit (2026-09-08)

A review of the game at version 1.0.7 through four installed Claude skills:
`supabase-postgres-best-practices` (Supabase, official), `systematic-debugging`,
`verification-before-completion` and `using-git-worktrees` (obra/superpowers),
`webapp-testing` (Anthropic) and `diagnosing-bugs` (mxyhi). Three audit agents
ran in parallel. Every line number below was read in this session; the backend
findings were also checked against the LIVE project (read-only, one probe run
inside `begin … rollback`). Nothing was edited. The previous audit is
`docs/AUDIT-2026-09-06.md`.

**Verdict:** the sim, the disc kit, the pins and the build scripts are strong.
The gaps are on the edges: the backend trusts one client number and grants more
than it needs, the crash record loses the facts a debugger needs first, and
nothing ever boots the real game in a browser before a store cut.

Severity: HIGH = fix before production. MED = fix soon. LOW = when convenient.

## 1. Backend (Supabase)

### B-1 (HIGH) — The boss tie-break sorts on a number the client makes up
- `supabase/functions/submit-run/index.ts:352` writes `p_time_sec: +run.timeSec || 0`
  straight from the request body. `verifyRun` returns no time (`_sim.mjs:31687-31689`,
  `scripts/build-verifier.js:149-150`).
- `migrations/20260821000000_boss_board_time_tiebreak.sql:42,51,63,118` rank, report
  and evict `%:7` boards by `time_sec asc`. `runs` has no `time_sec >= 0` check.
- A one-field edit (`timeSec: 0` or `-1`) with a valid JWT wins every boss tie.
- **Fix:** make `stats()` return `timeSec` (the sim already has `levelT`, `_sim.mjs:8270`),
  write `res.timeSec` for verified runs, and
  `alter table public.runs add constraint runs_time_nonneg check (time_sec >= 0 and combo_sec >= 0);`

### B-2 (HIGH) — No per-identity submission limit; the endless board is forgeable
- `submit-run/index.ts:258-260` accepts any endless score up to 100,000,000 with
  client-claimed stats. `schema.sql:225-234` evicts past 100 rows.
- `player_limits` (`schema.sql:262-265`) holds only `renamed_at`. Identities are
  free (`31-leaderboard.js:148-149`). The anonymous sign-in cap is only in the local
  `config.toml:202`; the hosted value is not in the repo.
- The verified path re-simulates up to 200,000 frames per request with no throttle.
- **Fix:** add `submitted_at`, `submit_count` to `player_limits` and gate inside
  `submit_verified_run` (10 per player per 10 minutes). For endless add a plausibility
  check (`p_score <= p_time_sec * MAX_RATE`). Confirm the hosted anonymous sign-in limit.

### B-3 (MED) — `submit_verified_run` is EXECUTE-granted to `anon` on the live project
- Live ACL: `anon=X, authenticated=X`. The repo says the opposite at `schema.sql:237-238`.
  Every other service-only RPC got an explicit revoke; this one never did.
- An `anon` probe reached statement 1 of the function and failed only at RLS.
- **Fix:** `revoke execute on function public.submit_verified_run(...) from public, anon, authenticated;`
  and `alter default privileges for role postgres in schema public revoke execute on functions from anon, authenticated;`

### B-4 (MED) — `anon` holds INSERT/UPDATE/DELETE/TRUNCATE on every table
- Live ACL `arwdDxtm` on `runs`, `reports`, `feedback`, `player_limits`,
  `runs_backup_20260902`. RLS alone stops the writes.
- **Fix:** `revoke insert, update, delete, truncate, references, trigger on public.runs from anon, authenticated;`
  `revoke all on public.reports, public.feedback, public.player_limits, public.runs_backup_20260902 from anon, authenticated;`
  plus the matching `alter default privileges … revoke all on tables`.

### B-5 (MED) — `schema.sql` no longer describes the live database
- No `trace_hash` (`20260821000001:20-21`), no boss tie-break in the three functions
  (`schema.sql:116,123,135,141,231`), no `feedback.error` (`20260906000000:17`).
- **Fix:** regenerate with `supabase db dump --schema public > supabase/schema.sql`
  at each release, or keep only tables there.

### B-6 (MED) — The replay-owner binding is evadable and stamped in a second transaction
- Any JWT holder can sign a URL for any public `trace_id` (`submit-run/index.ts:223-230`),
  alter one no-op frame, and the hash at `:320` no longer collides.
- The stamp at `:363-366` runs after the insert at `:349`; two concurrent submissions
  of the same stolen trace both pass `:321`.
- **Fix:** pass `p_trace_hash` into `submit_verified_run`; add
  `create unique index runs_trace_hash_uq on public.runs (trace_hash) where trace_hash is not null;`
  canonicalise frames before hashing. Longer term, seed the sim with the player id.

### B-7 (MED) — Personal data outlives the rows that justified it
- The `traces` bucket holds 293 objects, all orphans (`runs` has 0 rows since the
  2026-09-02 wipe). Each file name carries a player id and each body holds inputs.
- `runs_backup_20260902` (172 rows, 16 players, no primary key) is never touched by
  `delete_my_runs` (`schema.sql:306-315`).
- Upload-before-write (`submit-run/index.ts:337-342` then `:349`) adds an orphan on
  every failed RPC.
- **Fix:** purge the bucket now (batches of 100, as `my-data/index.ts:59-71` does);
  sweep the bucket in every wipe; drop the backup on a date, or add
  `delete from public.runs_backup_20260902 where player_id = p_player;` to `delete_my_runs`.

### B-8 (MED) — Deploy order: the repo's `send-feedback` calls an 8-arg `file_feedback` that is not live
- Migration `20260906000000` is not pushed. The deployed function (v1) sends no
  `p_error`; `send-feedback/index.ts:101` does.
- A function deploy before `db push` makes every note fail with PGRST202.
- **Fix:** `supabase db push` first, then `supabase functions deploy send-feedback --use-api`.

### B-9 (MED) — The feedback retention promise has no executor
- `20260901000000_feedback.sql:169-180` implements the 90-day rule; nothing calls
  `purge_old_feedback`. `pg_cron` is available and not installed.
- **Fix:** `create extension if not exists pg_cron; select cron.schedule('purge-feedback', '17 3 * * *', $$select public.purge_old_feedback()$$);`
  and a CHECK on the lengths of `error`, `build`, `device`, `screen`, `place`.

### B-10 (LOW) — `runs` has one CHECK and takes unbounded client arrays
- Only `score >= 0`. `player_name` has no length cap; `p_mutators` writes the raw array
  (`submit-run/index.ts:354`) while the package caps it at 8 (`:335`).
- **Fix:** CHECKs for non-negative stats, `char_length(player_name) <= 14`,
  `cardinality(mutators) <= 8`; slice `run.mutators` at `:354`.

### B-11 (LOW) — Check-then-write rate bars race
- `file_feedback` (`20260906000000:45-54`) and `rename_my_runs` (`schema.sql:276-288`).
- **Fix:** first statement `perform pg_advisory_xact_lock(hashtext(p_player));`

### B-12 (LOW) — 17 functions have a mutable `search_path` (advisor WARN)
- None is SECURITY DEFINER. `gen_random_bytes` in `20260813000800:19` would break
  under an empty path.
- **Fix:** `alter function … set search_path = '';` each, and write `extensions.gen_random_bytes(3)`.

### B-13 (LOW) — Redundant and unused indexes
- `runs_board_day_score` (`schema.sql:67`) indexes `day`, always NULL since
  `20260803000000:20-24`. `reports_created`, `reports_open`, `feedback_open` have 0 scans.
- **Fix:** drop the dead ones; replace `runs_trace_hash_idx` with the partial unique index from B-6.

### B-14 (LOW) — A run in flight across the Sunday turn is refused as "bad board"
- `submit-run/index.ts:182-186` requires `run.seed === weekOf(Date.now())` exactly.
- **Fix:** accept `live - 1` inside a 10-minute grace window.

### B-15 (LOW) — `service_role` has no `statement_timeout`
- Live: anon 3s, authenticated 8s, service_role none.
- **Fix:** `alter role service_role set statement_timeout = '15s';`

**Already fine:** RLS on for all five tables; no policy calls `auth.uid()`; no project
function is SECURITY DEFINER; all moderation, MY DATA, report and feedback RPCs are
revoked from anon; all six views are `security_invoker`; `verify_jwt = true` on all
four functions; the player id is always the JWT `sub`; the `traces` bucket is private
with 60s signed URLs; reads are bounded; the write is a true `insert … on conflict`;
the deployed `submit-run` is byte-identical to the repo (`a21d4685c45d`).

## 2. The error net and the release path

### E-1 (HIGH) — The crash record carries no stage, state, board or clock
- `src/game/99-boot.js:893-898`: `crashRecord` stores only `at / where / ver / build / msg`.
- `fbPlace()` (`31-leaderboard.js:402-408`) is evaluated at NOTE time, after the
  `location.reload()` at `99-boot.js:909`, so a lane crash reads `place: "menu"`.
- **Fix:** snapshot `fbPlace()`, `state`, `boardKey()`, `levelT`, `replaying`, `lowFX`,
  `W×H`, `DPR` and `performance.memory.usedJSHeapSize` inside `crashRecord`.

### E-2 (HIGH) — A later benign error overwrites the fault record
- `99-boot.js:915-916`: `error` and `unhandledrejection` both write the single slot
  `localStorage[FB_ERROR_KEY]` unconditionally. A rejected fetch on the reloaded
  session replaces the frame crash. No client-side dedupe.
- **Fix:** first-writer-wins for a `frame` record, or a 3-entry ring keyed by `where`;
  drop repeat messages inside N seconds.

### E-3 (HIGH) — No hook or script on the release path runs `npm test`
- `scripts/build-aab.sh:29-61` and `scripts/build-ios.sh:66-92` have no test step.
  `.githooks/pre-push:14-21` checks only verifier staleness, and `core.hooksPath` is unset.
- **Fix:** `npm test` as the first line of `build-aab.sh` after the key check;
  `pre-push` runs `npm test` before the verifier probe.

### E-4 (MED) — Android kills the app when the WebView renderer dies; iOS reloads
- `MainActivity.java:9-33` registers no `WebViewListener`, so Capacitor's
  `onRenderProcessGone` returns false and Android ends the process. iOS calls
  `bridge?.reset(); webView.reload()`. An OOM renderer death is the likeliest native
  crash, and the two shells answer it differently.
- **Fix:** a `WebViewListener` in `MainActivity` that records a marker and reloads,
  returns true; list the pair in BUILD.md.

### E-5 (MED) — Errors before the last script loads are neither recorded nor shown
- The listeners live at `99-boot.js:914-917`; `src/index.html:56-89` loads 33 scripts
  before it. A parse error in any earlier file leaves a navy canvas with no record.
- **Fix:** a minimal `error`/`unhandledrejection` listener in the inline stamp script
  at `src/index.html:55`; `99-boot.js` paints the fault disc if the slot is set and the
  loop never started.

### E-6 (MED) — `sync-version.js` claims success without checking a match
- `scripts/sync-version.js:61-68` does two regex replaces on `project.pbxproj` and
  prints success even with zero matches. No check reads `android/app/build.gradle`
  in `scripts/test.js`.
- **Fix:** count matches, exit 1 on zero, re-read after write, and pin the gradle
  `versionCode` / `versionName` next to the iOS pin at `test.js:6181-6184`.

### E-7 (MED) — `deploy:verifier` never probes the live RPC, and writes history early
- `package.json:10` is `build-verifier.js && supabase functions deploy submit-run`;
  no `verifier-status.js` after, no bundle test before, no `--use-api`.
  `scripts/build-verifier.js:178` writes `sim-history.json` before the deploy.
- **Fix:** `build:verifier && node scripts/test-verifier-bundle.mjs && supabase functions deploy submit-run --use-api && node scripts/verifier-status.js`;
  move the history write after a successful deploy.

### E-8 (MED) — No worktree convention in the repo
- CLAUDE.md has no "agent", "worktree" or "stash" text. The rule lives only in a
  private memory file. Six worktrees sit under `.claude/worktrees/`; five are fully
  merged; `worktree-sfx-volley-charge` holds an unmerged commit `8a11c6d` (dock-whine
  sfx, 2026-09-01).
- **Fix:** a CLAUDE.md section "Several agents, one checkout": every agent works in
  `.claude/worktrees/<task>`; never `stash`, `reset --hard`, `checkout .`, `add -A`;
  stage by explicit path; finish = merge, `git worktree remove`, `git branch -d`.
  Optional: a `PreToolUse` hook that denies those git forms in the main checkout.
  Decide `8a11c6d`; prune the five dead worktrees.

### E-9 (LOW) — Release scripts do not verify their outputs
- `build-aab.sh:40-42`: `cp` is the only existence check; no manifest dump against
  `package.json`. `build-ios.sh:89-91` prints "built" on a path it never tests.
- **Fix:** `bundletool dump manifest` and compare `versionName`; `[ -d "$APP" ] || exit 1`.

### E-10 (LOW) — CI is not `npm test`
- `.github/workflows/test.yml:22-30` skips `test-sfx-levels.mjs` and `test-verifier-bundle.mjs`.
- **Fix:** `run: npm test && node scripts/test-verifier-bundle.mjs`.

### E-11 (LOW) — No ring buffer of recent events, no repro pointer
- No log ring exists in `src/game/`. The record has no board key or trace frame.
- **Fix:** a 32-entry `evLog(tag)` in `00-core.js`; dump the last 10 into the record.
  On a frame fault in `S.PLAY`, store `boardKey()` and the trace frame count.

**Already fine:** the `frame()` guard is small, re-arms once, unwinds the ctx stack,
suspends audio and delays the restart tap 700 ms; the fault disc has a plain-text
fallback; the error slot is separate from the save blob; the outbox retries only on
transport failure; `set -euo pipefail` in all three build scripts; `build.js` refuses
to stage `dist/` if the stamp did not land; the server rate-limits error notes.
